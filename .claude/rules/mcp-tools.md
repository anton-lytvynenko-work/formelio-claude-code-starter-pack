## MCP Tools - Core Workflow Integration

### Claude Mem - Persistent Memory

**Purpose:** Cross-session memory that persists context automatically.

**When to use:**
- Storing project-specific context
- Remembering decisions and preferences
- Maintaining continuity across sessions

---

### Ref - Library Documentation & URL Reading

**Purpose:** Context-efficient library docs and URL content reading.

**When to use:**
- Library API documentation
- Framework guides and tutorials
- Reading specific URL content
- Code examples for specific libraries

**Query tips:**
- Include language and framework: `"Python pytest fixtures"`, `"TypeScript zod schema"`
- Be specific: `"SQLAlchemy async session management"` not just `"SQLAlchemy"`

---

### Context7 - Up-to-Date Library Docs

**Purpose:** Fetch current documentation for libraries and frameworks.

**When to use:**
- Getting latest API docs (avoids stale training data)
- Checking current best practices
- Looking up recent library changes

**Tip:** Use when Ref doesn't have recent enough docs or for rapidly-evolving libraries.

---

### Project-specific MCP servers

When a project configures additional MCP servers, document them in `.claude/rules/custom/mcp-tools.md` (auto-generated by `/implement` from `.mcp.json` if it exists). Per-server notes belong there, not here. Examples of what to record:
- Known limits (rate caps, key scope, missing privileges)
- Preferred entry points vs. tools that don't work
- "Discovery" workarounds when a list endpoint is denied

---

### Usage Priority

1. **Memory needs** → Claude Mem
2. **Library docs** → Ref (first choice) or Context7 (for latest)
3. **Specific URLs** → Ref
4. **Web search** → Built-in WebSearch tool

### Before Completing Work

- Verify code works (run tests)
- Check for type errors and linting issues
- Ensure no regressions introduced
